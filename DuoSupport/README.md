# DuoSupport 0.1.0

A deliberate-action reference and setup panel for **Evoker and Demon Hunter**, automatically selected from the player's class. Use the same addon on either person's installation, solo from each class's first playable level, including before specialisation unlock, or in a duo. There is **no minimum-level gate**: the live learned-spell list determines what appears. It does not select heals, evaluate health/cooldowns, suggest rotations, choose targets from combat state or execute casts automatically.

## Implemented and setup

1. Outside combat, `/duosupport setup` opens the panel. `/duosupport` toggles it. Panels can be dragged outside combat and closed with X.
2. Solo requires no partner setup. In a duo, `/duosupport partner Name-Realm` configures the actual companion. The other player sets your name on their own installation. Alternatively target your party partner and run `/duosupport select` outside combat. Blank `partner` clears it. Full name/realm avoids ambiguity; the addon resolves the current group explicitly rather than assuming party1. Set the other addons independently if enabled.
3. The panel displays detected class, actual level and native specialisation name (or not unlocked). Only learned entries from that class module appear. Evoker: healing/dispels, Quell, Obsidian Scales, Renewing Blaze, Hover and Rescue, with additional known healing-spec entries. Demon Hunter: personal sustain, Disrupt, Consume Magic, Blur, Demon Spikes, Darkness, Netherwalk, Fiery Brand, Fel Rush/Retreat and Metamorphosis, with native-reference-only ground/channel actions such as Infernal Strike/Fel Devastation. Demon Hunters do not acquire Evoker-style friendly off-healing. Names come from the client; unknown spells are absent. Class/spec/talent/level events refresh outside combat. The finite lists are not complete spellbooks, rotations or hard-coded level-unlock tables; they currently emphasise Havoc/Vengeance and shared DH utility, not a complete Devourer catalogue.
4. `/duosupport bind 351338 your-key` stores a **reference note**, not an actual binding. Use native Keybindings/action bars to bind Quell, defensives, movement and other controls. Choose any learned spell ID with a note; only entries in the panel's reference list are displayed.
5. Six secure buttons at the bottom show a static page of known actions. **Next actions** or `/duosupport page N` changes pages outside combat. Labels explicitly say **self**, **self (solo)**, **partner**, **partner not matched**, or **your target**. Each click requests one spell: self controls use the player, solo friendly controls use self, grouped friendly controls require the explicit partner match, and hostile utility controls use your own currently selected target. No enemy/party-slot/health-based target is chosen. There is no grouped self fallback for a missing partner. Ground/channel entries marked native-reference-only use your native action bars instead. Resource/range/cooldown/interactive-spell restrictions remain native. Read and test recipient labels before combat.
6. Evokers can alternatively use native unit-frame click-casting to choose each friendly recipient: **Options > Keybindings > Click Casting**, assign a known healing/dispel spell to your desired click/modifier, test it on Blizzard's party frame. The exact navigation/availability is client-owned; use Options search for “Click Casting” if needed. Demon Hunters should bind their own sustain/utility through native controls. DuoSupport does not create or overwrite native bindings.

Keep Blizzard's party frames visible for health and action bars/native cooldown displays visible for cooldowns. These are the supported initial presentation alternative: **DuoSupport does not read health, aura, range or cooldown state at all.** The optional DuoUI supplies passive bars. No threshold-based warning, interrupt recommendation, dispel detector or spell-availability-in-combat analysis is included. Native control setup and recipient behavior still need real-client validation.

## Planning profiles, commands and session use

- `/duosupport spec havoc` or `/duosupport spec vengeance` chooses a static planning profile manually. It does not change the player's actual specialisation. Actual player class/spec is detected separately; the companion's spec is not inferred.
- `/duosupport priority Your preparation priorities` and `/duosupport agreement Your agreed interrupt order` store text for the selected profile **within the detected class's plans**. Evoker and Demon Hunter plans are separate. Defaults are draft suggestions to agree together, not live prompts or confirmed agreements.
- `/duosupport check roles`, `check supplies`, `check bindings` toggle manual session checks. The Roles checked button toggles roles. Checkmarks reset on reload/login.
- Changes to partner/planning profile/bindings/action page or learned spells requested in combat wait until combat ends and then revalidate the current roster/known spells. Existing controls retain their last explicit recipient mode until then. Group-to-solo transitions in combat do not change a partner button to self until combat ends. Open the panel before a pull if using its buttons. Setup/toggle/close/drag and targeted-partner selection are out-of-combat operations.

## Installation on Windows and macOS

Keep `DuoSupport/DuoSupport.toc`, `Common.lua`, `Classes.lua` and `Main.lua` directly inside the addon folder. The existing Windows AddOns junction to `<REPOSITORY_PATH>` exposes it at `<RETAIL_ADDONS_PATH>`. On macOS use the [root whole-folder symlink instructions](../README.md#installation-and-first-use) with real local paths, never WTF. Restart to discover it, enable DuoSupport and use `/reload` for later edits. It has no mandatory dependency on the other addons.

## SavedVariables and reset

`DuoSupportDB` is account-wide, schema 2, in normal `WTF/Account/<account>/SavedVariables/DuoSupport.lua`. Partner, selected planning profile and binding notes remain account-wide; `classPlans` stores separate class priorities/agreements. Migration from schema 1 copies existing Evoker text into its class plan and retains legacy fields, binding notes and partner identity. Missing defaults merge non-destructively. Session checkmarks/action page are not saved. To reset, exit WoW, back up and remove only `DuoSupport.lua` and `.lua.bak` from SavedVariables, then restart. Native bindings remain separate. Back up WTF outside Git.

## Future ideas (not implemented)

More class modules, configurable reference entries, native binding navigation and accessibility improvements. To add a class, extend `NS.Classes` in `Classes.lua` with class token, guide, learned-spell entries and static planning defaults. Choose `self`, `partner` or `target` only for supported explicit secure controls; leave `action` absent for reference-only abilities. Do not add level gates or infer availability from combat state. Add learned-only/solo/recipient/migration tests and real starting-character checks. Additional combat presentation requires fresh API validation; automated healing/target selection and rotation execution remain excluded.
