# API evidence and initial design limits

Reviewed 24 October 2026 against Blizzard's generated API documentation and UI implementation mirrored by [Gethe/wow-ui-source, live](https://github.com/Gethe/wow-ui-source/tree/live). The inspected [version.txt](https://github.com/Gethe/wow-ui-source/blob/live/version.txt) reports **12.1.5.70575**, matching the installed client's build. These `live` links may move; re-check their version marker after patches. This review did not use exported Blizzard source from the client. Source review establishes feasibility, not successful in-game execution.

## DuoBags

[ContainerDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ContainerDocumentation.lua) defines container slots/free space, item/quest structures and `UseContainerItem`. The native [ContainerFrame.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.lua) uses that item action and the `AUTOLOOTTOGGLE` modifier. Sale is limited to a deliberate out-of-combat click at a vendor, with a revalidated single-use snapshot, and excludes equippable/quest/locked/uncached/loot-container/no-value/non-grey/keep/Companion items. It never calls sell-all-junk. Vendor restrictions remain authoritative; if blocked, sell manually through native bags using the preview as a reference. No automatic retry or bypass.

[CVarDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/CVarDocumentation.lua) defines public CVar access and scope metadata. `autoLootDefault` is changed only by the toggle or explicit on/off command. Its current default and effective value (native modifier inversion) are shown; `GetCVarInfo` reports server account/character storage or local/shared storage in the panel. Local/shared settings can affect other characters on the same installation; server-account settings affect that account. The toggle is not a per-addon override. Existing modifier bindings and loot confirmation handling are untouched. It collects eligible loot only through the normal client behavior once you open loot; there are no loot-slot, movement, targeting or interaction automation calls.

[ChatInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua) defines `CHAT_MSG_LOOT` text and sender GUID. DuoBags counts only accessible self-GUID messages containing item links. Secret chat payloads are skipped. Item stack counts parse the `xN` suffix used by the installed enUS client; localized quantity formats and events lacking a usable self GUID may be omitted/undercounted. This is a lightweight session receipt log, not a complete financial or inventory ledger. No tooltip scraping or restricted-data reconstruction is used.

## DuoUI and DuoSupport

[SimpleStatusBarAPIDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleStatusBarAPIDocumentation.lua) explicitly marks `SetMinMaxValues` and `SetValue` as `AllowedWhenTainted`, with `BarValue` secret aspect propagation. DuoUI passes `UnitHealthMax`/`UnitHealth` straight into those methods. No arithmetic, comparisons, text formatting, cached health, health-based colors or suggestions. Only unit event tokens are compared. Identity/layout refresh is outside combat; a changed combat roster clears the partner bar until a fresh roster can be resolved. Native frames remain available throughout.

[SecureTemplates.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_FrameXML/SecureTemplates.lua) defines the secure spell action and unit attribute. DuoSupport configures secure spell/unit attributes outside combat only. Class modules define explicit self, partner or user's selected-target controls; grouped friendly controls use the resolved character's full name, never a persistent party slot. Solo friendly controls explicitly use self. Missing grouped partners disable friendly controls. Combat configuration is revalidated on `PLAYER_REGEN_ENABLED`. Native health/resource/cooldown UI remains responsible for combat state presentation; ground/channel controls can remain reference-only. Native Click Casting is an Evoker alternative; no native bindings are overwritten.

[SpellBookDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpellBookDocumentation.lua) supplies learned-spell checks. DuoSupport's `Classes.lua` contains separate Evoker/Demon Hunter registries and class planning defaults; the generic controller filters them against the actual spellbook, uses localized spell names and never applies a minimum-level gate. UnitClass detects the player automatically; native spec information is informational, while Havoc/Vengeance planning selection remains manual. Schema-2 migration retains earlier Evoker text. Lists are finite (shared/Havoc/Vengeance DH emphasis, not complete Devourer coverage). Actual starting unlocks, talent replacements, secure full-name recipients and single-action key-down/up behavior still need in-game checks.

## DuoSocial

[PartyInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/PartyInfoDocumentation.lua) defines `CanInvite` and `InviteUnit`; the latter preserves native invitation confirmations. [GuildInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/GuildInfoDocumentation.lua) defines asynchronous guild roster requests. Native roster functions supply names, roles, leader/assistant and online state. Roster presentation pauses during combat rather than assuming those fields are unrestricted. Ready checks are explicit and gated by leader/assistant permission; WoW remains responsible for contextual restrictions. Group-management scope in v0.1 is inviting plus ready checks, not destructive group edits. No guild-note setter, addon comms or chat-send API is used.

`DuoSocialAPI.SetActivity(text)` is an optional local out-of-combat integration used by DuoAdventure's explicit Social plan action. It does not send or sync the activity text.

## DuoAdventure

[QuestLogDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua) provides exposed log entries, objectives, completion, objective-distance estimates, party overlap and local quest shareability. The planner reads these outside combat. Immersion preserves native order; speed applies a deterministic, documented accepted-quest heuristic. It does not discover unknown quests or calculate an optimal route. Share/catch-up advice distinguishes native same-quest evidence, missing reports and unknown/offline data; shareability is not recipient eligibility. [QuestMapFrame.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/QuestMapFrame.lua) supplies feature-detected native detail navigation and native sharing controls. Actual sharing stays manual in that native UI.

The user's explicit communication request authorizes automatic party-addon updates after opt-in. [ChatInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua) supplies prefix registration, messages/results and lockdown checks. V2 adds a party-join checkbox prompt, session consent, event-debounced broadcasts and a 30-second refresh. Saved preferences only preselect the prompt; each party session needs approval. Numeric objective `numFulfilled/numRequired` fields and quest events in the generated quest docs support incremental counts before an objective finishes. At most six accessible progress pairs per quest are serialized; notes/text are excluded. Receivers validate membership, channel, bounds and assembly; pushes require opt-in and request replies require their nonce. Combat cancels transfers; fresh public state is rebuilt after combat. Chat-only restrictions recover on periodic refresh. No restricted value is serialized. A two-peer virtual-clock model covers automatic updates and restriction recovery; actual two-client/native restrictions remain unverified.

### Native Party Sync boundary (DuoAdventure 0.3.0)

Reviewed 25 October 2026 at the pinned mirror commit [15881d5](https://github.com/Gethe/wow-ui-source/tree/15881d522c44cd106d3d8660106ec9f9d2f44167), whose `version.txt` reports 12.1.5.70575. [QuestSessionDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/15881d522c44cd106d3d8660106ec9f9d2f44167/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestSessionDocumentation.lua) defines the Party Sync queries `Exists`, `HasJoined`, `HasPendingCommand` and `GetPendingCommand` (values from `Enum.QuestSessionCommand` in the constants documentation), the commands `RequestSessionStart`, `RequestSessionStop`, `SendSessionBeginResponse` and `SetQuestIsSuperTracked`, and the lifecycle events. `DuoAdventure/Native.lua` uses only the four queries and registers only `QUEST_SESSION_CREATED`, `DESTROYED`, `JOINED`, `LEFT`, `ENABLED_STATE_CHANGED` and `NOTIFICATION`, each after `C_EventUtils.IsEventValid` accepts it when that check exists. A missing API or a nil, secret or non-boolean answer is reported as unknown, never as inactive.

In Blizzard's [QuestSession.lua](https://github.com/Gethe/wow-ui-source/blob/15881d522c44cd106d3d8660106ec9f9d2f44167/Interface/AddOns/Blizzard_FrameXML/QuestSession.lua) the session commands are called only from its own start/stop dialog `Confirm`/`Cancel` handlers. A GitHub code search of the mirror at that commit found those command names only in that file and the generated documentation. [QuestMapFrame.lua](https://github.com/Gethe/wow-ui-source/blob/15881d522c44cd106d3d8660106ec9f9d2f44167/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/QuestMapFrame.lua) starts or stops a session only from the Party Sync button click (`QuestSessionManagementMixin:OnClick`), which opens a check dialog first. `QuestMapFrame_OpenToQuestDetails` and `ToggleQuestLog`, the only native windows DuoAdventure opens, set the display mode and show the log or details. [PartyInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/15881d522c44cd106d3d8660106ec9f9d2f44167/Interface/AddOns/Blizzard_APIDocumentationGenerated/PartyInfoDocumentation.lua) says `InviteUnit` and invite requests may need confirmation while Party Sync is in progress. QuestSession.lua answers those through dialogs that call `ConfirmInviteUnit`, `ConfirmRequestInviteFromUnit`, `ConfirmInviteTravelPass`, `ConfirmBNRequestInviteFriend` or `AcceptGroup` only on the player's click. No addon in this suite calls any of these commands or confirmation functions, hooks or clicks those dialogs, or registers the confirmation events; `tools/check-repository.py` enforces this. Source review does not prove runtime values, that the queries are unrestricted in every context, or who started a given session.

## Remaining verification

All runtime APIs require actual client checks despite source review. No claim of in-game Windows, macOS, PvP, instance-combat, private-aura, cooldown or secure-action verification is made. See each README and `VERIFICATION.md` for repeatable tests. Missing runtime features should be handled through native UI rather than alternate restricted-state APIs.
